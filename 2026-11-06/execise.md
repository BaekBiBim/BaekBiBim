# Git과 GitHub 실습 문제

> 기존 프로젝트가 아닌 별도의 연습용 폴더와 테스트 저장소에서 진행하세요. 공개 저장소에는 개인정보나 비밀번호를 올리지 않습니다.

## 1. 저장소와 변경 상태

1. 연습용 폴더를 만들고 `git init`으로 저장소를 초기화하세요.
2. 텍스트 파일을 만든 다음 `git status`로 추적되지 않는 파일을 확인하세요.
3. `git add <파일명>`과 `git commit -m "첫 커밋"`으로 기록하세요.
4. `git log --oneline`으로 커밋을 확인하세요.

**생각해 보기:** 작업 폴더, 스테이징 영역, 커밋은 각각 어떤 역할을 하나요?

## 2. 브랜치와 병합

1. 현재 브랜치를 `git branch --show-current`로 확인하세요.
2. `git switch -c feature/practice`로 새 브랜치를 만들고 파일을 변경해 커밋하세요.
3. 원래 브랜치로 돌아간 뒤 `git merge feature/practice`로 병합하세요.
4. `git log --oneline --graph --all`로 브랜치와 커밋 관계를 확인하세요.

**생각해 보기:** 다른 브랜치에서 작업하면 어떤 이점이 있나요?

## 3. 충돌 해결

1. 연습 저장소의 두 브랜치에서 같은 파일의 같은 줄을 서로 다르게 수정하고 각각 커밋하세요.
2. 한 브랜치에서 다른 브랜치를 병합해 충돌을 확인하세요.
3. `git status`와 파일 안의 `<<<<<<<`, `=======`, `>>>>>>>` 표시를 살펴보세요.
4. 두 변경의 의미를 확인하고 필요한 내용을 남긴 뒤 충돌 표시를 제거하세요.
5. `git add <파일명>`으로 해결을 표시하고 `git commit`으로 병합을 완료하세요.
6. `git status`로 병합이 끝났는지 확인하세요.

**생각해 보기:** 양쪽 변경을 모두 남기는 것이 언제나 올바른 해결 방법일까요?

## 4. GitHub CLI와 원격 저장소

1. `gh auth status`로 로그인 상태를 확인하세요.
2. 테스트용 Git 저장소에서 다음 명령으로 **비공개** 원격 저장소를 만들어 연결하세요. `<저장소명>`을 본인이 정한 이름으로 바꾸세요.

   ```bash
   gh repo create <저장소명> --private --source=. --remote=origin
   ```

3. `git remote -v`로 연결 주소를 확인하고 `git push -u origin <브랜치명>`으로 커밋을 올리세요.
4. `gh issue create --repo <계정>/<저장소명>`으로 이슈를 만들어 보세요.

**주의:** 원격 저장소 생성은 실제 GitHub 계정에 영향을 줍니다. 이름과 공개 범위를 먼저 확인하세요.

## 5. Pull Request

1. 테스트 저장소에서 `git switch -c release`로 브랜치를 만드세요.
2. 파일을 변경하고 커밋한 뒤 `git push -u origin release`로 올리세요.
3. 기본 브랜치가 `main`인 경우 다음 명령으로 PR을 만드세요.

   ```bash
   gh pr create --base main --head release --title "실습 변경" --body "변경 내용과 확인 방법을 정리합니다."
   ```

4. GitHub에서 변경 파일과 PR 내용을 확인하세요. 병합은 검토 후 진행하세요.

**생각해 보기:** PR 본문에 변경 이유, 확인 방법, 주의 사항을 적으면 어떤 도움이 되나요?
